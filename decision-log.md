# Decision Log: Earnings Report RAG Chat System

> Complete, unfiltered record of every architecture decision settled while
> producing the system design for `PRD.md`. Every row here traces to
> either a PRD section (stated as fact) or a grilled question (answered by
> the user). Nothing here was assumed.
>
> This is the full record. Only decisions that pass the three-part ADR bar
> get a standalone ADR — most rows won't, and that's expected. Qualifying
> decisions are written up by the `adr-generator` skill, not drafted inline
> here.

| # | Decision | Answer | Source | ADR? |
|---|----------|--------|--------|------|
| 1 | Chat interface medium | Streamlit web app, calling the RAG pipeline in-process (no separate REST API for v1) | Grilled Q1 | `docs/adr/ADR-001-chat-interface-streamlit.md` |
| 2 | External links to substantiate answers | Deferred out of v1 scope entirely (not just deferring the mechanism choice) — see PRD §3 (Non-Goals) and §11 (Future Enhancements) | Grilled Q2 (user overrode: descope rather than pick a mechanism) | — |
| 3 | LLM provider for answer generation | Anthropic Claude Haiku (`claude-haiku-4-5-20251001`), replacing the hardcoded `ChatOpenAI` in `prototype/rag/pipeline.py` with `langchain-anthropic`'s `ChatAnthropic` | Grilled Q3 | — (low switching cost — provider is a single-class swap behind one interface — doesn't clear "hard to reverse") |
| 4 | Data folder organization | Reorganize into per-company subfolders, `data/<TICKER>/*.pdf`; `company` metadata derived deterministically from the parent folder name. Solves company attribution only — quarter/year metadata derivation remains open (row 6, pending) | Grilled Q4, informed by anticipated year-over-year query support | `docs/adr/ADR-002-data-folder-organization.md` |
| 5 | Vector store backend | Chroma (local persistent-client mode, no server process), retiring FAISS as the default. Evaluated against FAISS, Qdrant, and Pinecone on cost/scalability/query speed/metadata filtering; Pinecone disqualified outright (cloud-only, conflicts with local-only NFR); Qdrant deferred (needs a server process, distributed-scale strengths unneeded at this project's scale) | Grilled Q5 | `docs/adr/ADR-003-vector-store-chroma.md` |
| 6 | Chunking / page-citation strategy | Merge each PDF's pages into one text blob per document before chunking, allowing chunks to span page boundaries; page citation becomes a range (e.g. "pp. 11-12") derived from tracking character-offset-to-page-boundary mapping. Note: structural within-page chunking (exact single-page citation) was the true zero-effort default — confirmed by testing LangChain's `split_documents()`, which never merges across the separate per-page `Document`s `PyPDFLoader` produces. Cross-page merging requires new implementation, not a config flag | Grilled Q6 (corrected mid-discussion: initial framing of cross-page as "already default" was verified false and retracted before this decision was made) | `docs/adr/ADR-004-cross-page-chunking.md` |
| 7 | Ingestion trigger & change detection | Ingestion is a separate, explicitly-invoked command (`ingest.py`), run manually by the user on their own cadence (typically aligned with quarterly earnings releases) — never auto-triggered by the Streamlit chat app at startup. Each run fully re-processes all PDFs under `data/<TICKER>/` rather than tracking a hash/mtime manifest; the chat app only reads the already-persisted Chroma store. Overrides an earlier proposal (auto-ingest on startup + manifest) once the actual release cadence was considered | Grilled Q7 | `docs/adr/ADR-005-ingestion-trigger.md` |
| 8 | Conversation memory for multi-turn | Retrieval is conversation-aware (not retrieval-naive): bounded window of last N raw turns feeds both retrieval-query construction and the generation prompt; turns aging out of the window are folded into a running LLM-generated compaction summary; a structured episodic-memory list of extracted facts (company, metric, quarter, value) is held in session state for mid-session recall after compaction. Episodic memory is explicitly in-session only (ephemeral) — cross-session persisted recall was considered and rejected as an unstated scope increase beyond current PRD goals | Grilled Q8 | `docs/adr/ADR-006-conversation-memory.md` |
| 9 | LLM unavailability fallback | One unified fallback: whenever the LLM is unavailable — no API key at startup (Q9), or a runtime call failure (exception/timeout/rate-limit) — the app degrades to a retrieval-only response (raw matching excerpts + citations, no LLM-generated answer) with a clear on-screen notice, instead of refusing to start or crashing. Extends the original Q9 (missing-key-at-startup) scope to also cover runtime LLM call failures | Grilled Q9 (extended) | `docs/adr/ADR-007-llm-fallback.md` |
| 10 | Quarter/year metadata derivation (PRD §9 item 4) | Extract from each PDF's own content via regex/keyword search on page-1 (and early-page fallback) text for common reporting-period patterns — not an LLM call, not a manifest. When no pattern confidently matches, ingest the file anyway with `quarter`/`year = unknown`; such chunks are excluded from period-scoped and year-over-year filtering but remain retrievable for general/company-scoped questions. Overrides both recommended alternatives (LLM extraction; skip-and-report on failure) | Grilled Q11 + Q12 | `docs/adr/ADR-008-quarter-year-extraction.md` |
| 11 | Vector store missing/corrupted at chat-app startup | Show a clear error directing the user to run `ingest.py` first. No auto-rebuild (would silently reintroduce the auto-ingest-on-startup behavior ADR-005 rejected) and no degraded empty-chat fallback (would look like a working app that mysteriously finds nothing) | Grilled Q13 | — (low reversal cost, thin trade-off; a direct application of ADR-005's reasoning, not an independent fork) |
| 12 | Malformed/unreadable PDF during ingestion | Detect near-empty extracted text and skip that file with a warning in the `ingest.py` run summary, rather than ingesting it (no usable text = pure retrieval noise, unlike the partial-value case in row 10) or hard-failing the whole batch | Grilled Q14 | — (low reversal cost — an ingestion-time filter, easy to change later; a direct application of the "don't block the whole batch on one bad file" pattern from rows 7 and 10) |
| 13 | Ticker folder name canonicalization | Validate ticker folder names at ingestion time; warn/reject names that aren't a clean uppercase ticker (e.g. flag "Google" or "google" instead of "GOOGL") | Grilled Q15 | — (low reversal cost; direct extension of ADR-002's folder-based company attribution, not an independent fork) |
| 14 | Embeddings provider | Explicitly confirmed: keep the existing prototype default, HuggingFace `sentence-transformers/all-MiniLM-L6-v2` (local, free). No requirement in this design surfaced a reason to change it | Grilled Q16 | — (not a change, just a confirmation of an existing default — no real trade-off being actively chosen) |
